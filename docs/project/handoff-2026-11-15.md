## Decisions made so far

- **Robot:** XGO-Duck redesigned for 15 Feetech SCS0009 servos at 0.92 scale, Arduino UNO Q.
- **Licences:** Apache-2.0 for code and docs, CC BY-NC-SA 4.0 for hardware files. XGO-Duck-derived shells are not
  published until Luwu Dynamics' permission is confirmed.
- **Software split:** the microcontroller firmware stays C++ until the robot walks; the Linux side is Rust on rigrs.
  Gaps in rigrs are fixed upstream by pull request, asking before pushing there. trainnr is used through its MCP
  tools only; its gaps are reported as issues, not fixed here or in a checkout (2026-11-15). Filed so far:
  [Trainnr-AI/trainnr](https://github.com/Trainnr-AI/trainnr/issues) issues #100 to #108. #102 to #108 were fixed
  upstream on 2026-11-15 (trainnr pull request #109); #100 (walk family) and #101 (servo fit) are open. The fixes
  reach a machine only when its trainnr plugin is updated.
- **Bench motion:** one servo may be moved on its own only in a bench build (`DUCK_BENCH_MOTION 1`, off by default),
  under supervision; the board runs the default build.
- **Deferred:** the 3D design fixes; a Bluetooth speaker for sounds and a Bluetooth gamepad for commands (the board
  has Bluetooth 5.1 and PipeWire; nothing paired yet).
- **Repository layout** follows Pollen Robotics' Microduck.
- **Not safe for children yet:** the design review's findings (battery protection, clearances, collisions inside the
  documented limits) are open.

## Things that are easy to get wrong

- The repository's sketch and this board disagree on link speed (see above).
- `duckd run --exchange state` or `step` refuses a board whose app speaks a protocol older than 4.
- Stopping the app also stops the sketch on the microcontroller; its LEDs and the matrix go dark.
- The cross-build of the runtime needs `cargo-zigbuild` ([runtime/README.md](../../runtime/README.md)).
- `duckd run` on a bare board reports every chain "unmeasured" and skips the policy every tick. That is correct:
  no servo answers.
- The benchmark and review numbers are from one board and one design revision. Re-measure before relying on them,
  and not while something else is compiling on the board (that alone doubled inference times once).
- `duckd run --policy` takes a trainnr deployment folder (`policy.onnx` + `deploy.json`), not the old manifest.
- trainnr's current project: with a plugin from before 2026-11-15 it is shared by every session and by the Studio
  (trainnr#104, fixed upstream since): a session that switches it switches it for the others. Call `use_project`
  first. `microduck-nano` is ours; the design session works in `xgoduck_scs0009`.
- Piping `adb shell` output into `head` can kill the remote command when `head` exits (an app start was cut short
  that way once). Redirect to a file instead.
