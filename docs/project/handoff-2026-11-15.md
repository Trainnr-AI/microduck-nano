## The test board (one Arduino UNO Q, 4 GB)

Its state differs from a board out of the box. A second board will not have any of this.

- **Software updated:** App CLI 0.14.1, router 0.11.0, `arduino:zephyr` core 1.1.0. Wi-Fi is configured.
- **Admin password set** for the `arduino` user. It is not written anywhere in this repository; ask the owner.
- **`arduino` is in the `arduino-router` group**, so programs it runs can use the router socket.
- **Link speed raised to 460800 baud** by `/etc/systemd/system/arduino-router.service.d/90-microduck-link-speed.conf`.
  Arduino App Lab's own examples will not talk to Linux on this board until
  `sudo sh set-link-speed.sh default` is run.
- **The app on the board is built for 460800:** `/home/arduino/ArduinoApps/microduck/sketch/duck_build_config.h`
  there has `DUCK_BRIDGE_BAUD 460800`. The repository's default is 115200. **Pushing the app from the repository
  as it is will break the link** until that line is changed on the board again (or the router is set back).
- **App:** `Microduck Nano`, bench-safe build, firmware protocol 2. It is not the default app, so after a restart
  it must be started by hand (`arduino-app-cli app start /home/arduino/ArduinoApps/microduck`).
- **Files left on the board:** `/home/arduino/duck/` (the `duckd` binary, `robot.json`, a random test policy,
  `set-link-speed.sh`) and `/home/arduino/bench/` (about 1.1 GB of benchmark tools and models; safe to delete).
- **Nothing is wired to it:** no servo, no IMU, no camera, no battery.

Reaching it: `adb` over USB-C. On macOS and Linux `adb` sees the board directly; on Windows with WSL, run the
Windows `adb.exe` from WSL ([build-and-flash.md](../robot/build-and-flash.md)).

- **Robot:** XGO-Duck redesigned for 15 Feetech SCS0009 servos at 0.92 scale, Arduino UNO Q.
- **Licences:** Apache-2.0 for code and docs, CC BY-NC-SA 4.0 for hardware files. XGO-Duck-derived shells are not
  published until Luwu Dynamics' permission is confirmed.
- **Software split:** the microcontroller firmware stays C++ until the robot walks; the Linux side is Rust on rigrs.
  Gaps in rigrs and trainnr are fixed upstream by pull request, asking before pushing there.
- **Repository layout** follows Pollen Robotics' Microduck.
- **Not safe for children yet:** the design review's findings (battery protection, clearances, collisions inside the
  documented limits) are open.

## Things that are easy to get wrong

- The repository's sketch and this board disagree on link speed (see above).
- The repository's firmware speaks protocol 3 (the gyro in the state message); the board still runs protocol 2.
  `duckd run --exchange state` or `step` refuses the board until the app is pushed again (mind the link speed).
- Stopping the app also stops the sketch on the microcontroller; the red LED goes dark.
- The cross-build of the runtime needs `cargo-zigbuild` ([runtime/README.md](../../runtime/README.md)).
- `duckd run` on a bare board reports every chain "unmeasured" and skips the policy every tick. That is correct:
  no servo answers.
- The benchmark and review numbers are from one board and one design revision. Re-measure before relying on them.
