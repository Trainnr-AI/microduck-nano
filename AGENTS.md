# AGENTS.md

Instructions for coding agents working in this repository (Claude Code reads them through `CLAUDE.md`). People: the
same rules, with reasons, are in [`CONTRIBUTING.md`](CONTRIBUTING.md).

Open-source build of Microduck Nano, a new smaller variant derived from the Microduck biped (Pollen Robotics), from parts to a walking policy on the real robot. Public repository: write everything for a stranger who wants to build one.

Licences: Apache-2.0 for code, configs and docs (`LICENSE`); CC BY-NC-SA 4.0 for hardware files and meshes (`LICENSE-MODELS.md`).

Continuing from another machine or session: read `docs/project/handoff-2026-11-15.md` first. It records the test
board's state and what is not in the repository.

## Layout

Modelled on Pollen Robotics' Microduck repositories.

| Path | What |
|---|---|
| `firmware/` | What runs on the Arduino UNO Q, its limits file (`config/robot.json`) and host tests |
| `scripts/` | Tools run by hand: board benchmarks (`uno-q-bench/`), design-review scripts (`design-review/<date>/`) |
| `docs/robot/` | For someone with a robot: build, flash, bench checklist |
| `docs/design/` | How things work |
| `docs/project/` | Dated records: roadmap, reviews, measurements, prior art |
| `runtime/` | The Linux-side runtime, in Rust, built on rigrs (`Trainnr-AI/rigrs`): firmware client, control loop, policy runner. Gaps found in rigrs are fixed upstream by pull request, like trainnr; see `docs/project/rigrs-for-general-use.md` |
| `hardware/`, `robot/`, `training/` | Not here yet |

Before saying a firmware change is done: `python3 firmware/tools/gen_config.py --check` and `make -C firmware/tests test`.
Before saying a runtime change is done: `cargo test` and `cargo clippy --all-targets` in `runtime/` (no warnings).

## How work is done here

- **Sim, training and deployment go through the trainnr MCP server** (`mcp__trainnr__*`) and are checked in trainnr Studio (`launch_studio`, `screenshot_studio`). Do not script around trainnr with ad-hoc MuJoCo or training code.
- trainnr project: `microduck-nano` (`use_project` at the start of a session; `describe_project` gives the loop state and the next move). Its data lives under `$TRAINNR_HOME/projects/microduck-nano`, outside this repository.
- The robot is onboarded in that project as `microduck-nano` (16 bodies, 15 joints, 14 position actuators; the mouth servo is not actuated in the model). Editing the model means onboarding again, which changes its stamp.
- trainnr's library also carries `microduck` (Pollen's original, XL330 servos) as a reference.

## Where the robot comes from

The design source is the separate `agent-cad3d` repository (`Trainnr-AI/agent-cad3d`, usually checked out beside this one), project `projects/xgoduck_scs0009/`: XGO-Duck redesigned for 15 Feetech SCS0009 servos at uniform 0.92x scale, head shell 0.85x, Arduino UNO Q. Read its `docs/HANDOFF.md` and `projects/xgoduck_scs0009/REVIEW.md` before touching the design; decisions and open items live there.

- Simulation model: `projects/xgoduck_scs0009/sim/scene_scs0009_v1.xml` (includes `robot_scs0009_v1.xml`, meshes in `sim/assets_v1/`). Its masses and inertias still come from the scaled original, not the new parts.
- CAD is edited there (Blender over MCP), not here. This repository receives finished, checked outputs.
- No SCS0009 actuator model exists yet: it must be identified from real telemetry (`identify_system`) before a trained policy means anything.

## Publishing meshes: check first

Body and head shells are scaled copies of XGO-Duck STLs. XGO-Duck's hardware repository has **no licence file**; its `LICENSING.md` states only an intent to allow personal and educational replication and asks that permission be confirmed before redistributing derivatives. Do not copy XGO-Duck-derived meshes (or the `.blend`) into this public repository until the user confirms permission. Parts generated by our own scripts and the Feetech-derived servo mesh are a separate question; ask rather than assume.

## When trainnr lacks a feature or has a bug

Report it upstream; do not work around it here. trainnr is used through its MCP tools only: do not clone it or
change its code (the owner's decision, 2026-11-15).

1. Open an issue in `Trainnr-AI/trainnr` describing the general feature or bug (for everyone who uses trainnr, not
   only this robot), with what you saw and how to see it again. Search its issues first.
2. If it blocks work here, open an issue in this repository that links to it, and say so where the work is
   recorded (roadmap, handoff, `docs/design/sim-to-real.md`).

## Rules for this repository

- No machine-specific paths (`/home/...`) in committed files.
- Anything derived from Pollen's 3D models is CC BY-SA-NC: keep attribution, never relicense it.
- Numbers (success rates, fitted parameters) come from trainnr records; cite the record's stamp instead of typing a number from memory.
- Keep the README's status line true.
